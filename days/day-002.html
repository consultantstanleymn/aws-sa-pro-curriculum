1. Deep Architectural Mechanics: Advanced SCP Conditions

Global Condition Keys in SCPs

Standard IAM policies evaluate conditions at the identity level. When used in SCPs, global condition keys act as organization-wide cryptographic and network barriers:

  • aws:PrincipalOrgID: Restricts resource access to identities belonging to your specific AWS Organization. Commonly used in S3 Bucket Policies and KMS Key Policies to allow access to all current and future accounts in your organization with a single condition block, eliminating manual account ARN updates.
  • aws:RequestTag/${TagKey} vs. aws:ResourceTag/${TagKey}:
    • aws:RequestTag: Evaluates tags passed in the API request (e.g. creating an instance or volume). Used to mandate tag presence at creation time.
    • aws:ResourceTag: Evaluates existing tags on resources. Used to control operations (e.g. start/stop/terminate) based on resource environment.
  • aws:SourceVpc & aws:sourceVpc: Restricts S3, KMS, and API operations so they can only be invoked from within designated private VPCs or via AWS PrivateLink VPC endpoints.

The Explicit Deny Inheritance Rules

Understanding policy inheritance across nested OUs is one of the most heavily tested topics on the SAP-C02:

Attachment Level Policy Statement Inheritance Behavior in Child OU
Root OU FullAWSAccess (Allow *) Baseline ceiling. Allows services unless a downstream policy denies them.
Parent OU Explicit Deny on s3:DeleteBucket Irreversible across all sub-OUs and member accounts. No child policy can ever grant DeleteBucket.
Child OU Explicit Allow on s3:DeleteBucket with condition Completely ignored. Deny at parent level takes absolute precedence.
Member Account IAM AdministratorAccess Constrained by parent SCP. The administrator cannot delete S3 buckets.

2. Production SCP Blueprints (Copy-Pasteable JSON)

Blueprint 1: Mandatory Tag Enforcement on Resource Creation (ABAC)

Denies creating EC2 instances or EBS volumes unless tagged with Environment (Prod, Stage, or Dev) and a valid CostCenter:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "EnforceEnvironmentAndCostCenterTags",
      "Effect": "Deny",
      "Action": [
        "ec2:RunInstances",
        "ec2:CreateVolume"
      ],
      "Resource": [
        "arn:aws:ec2:*:*:instance/*",
        "arn:aws:ec2:*:*:volume/*"
      ],
      "Condition": {
        "Null": {
          "aws:RequestTag/Environment": "true",
          "aws:RequestTag/CostCenter": "true"
        }
      }
    },
    {
      "Sid": "EnforceValidEnvironmentValues",
      "Effect": "Deny",
      "Action": [
        "ec2:RunInstances",
        "ec2:CreateVolume"
      ],
      "Resource": [
        "arn:aws:ec2:*:*:instance/*",
        "arn:aws:ec2:*:*:volume/*"
      ],
      "Condition": {
        "StringNotEquals": {
          "aws:RequestTag/Environment": ["Prod", "Stage", "Dev"]
        }
      }
    }
  ]
}

Blueprint 2: Enforce S3 Encryption in Transit (TLS 1.2+) & Block HTTP

Attaching this guardrail guarantees that data in transit across all S3 buckets in member accounts cannot be intercepted via plain HTTP:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyNonSecureTransport",
      "Effect": "Deny",
      "Action": "s3:*",
      "Resource": "*",
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}

3. Comprehensive SAP-C02 Scenario Practice Questions

Scenario 1: aws:PrincipalOrgID for Shared S3 Buckets
An enterprise operates a centralized data lake bucket in a Shared Services account. Applications across 60 member accounts read datasets from this bucket. New AWS accounts are added weekly through automated pipelines. Currently, the S3 bucket policy explicitly lists all 60 account IDs in the Principal element, hitting the maximum 20 KB bucket policy size limit. How can the solutions architect refactor this policy to scale indefinitely with the LEAST operational maintenance?
A) Create multiple replica buckets and partition accounts across them using Route 53 geolocation routing.
B) Replace individual account IDs in the Principal element with Principal: "*" and add a condition StringEquals: { "aws:PrincipalOrgID": "o-xxxxxxxxxx" }.
C) Create an IAM role in the Shared Services account and have applications in all member accounts assume it via STS.
D) Deploy an AWS Lambda function triggered on account creation to compress the S3 bucket policy JSON.
Correct Answer: B.
Architectural Rationale: The aws:PrincipalOrgID global condition key checks whether the principal making the request belongs to an account in the specified organization. Setting Principal: "*" with Condition: { StringEquals: { "aws:PrincipalOrgID": "o-xxxxxxxxxx" } } allows all current and future accounts in the organization to access the bucket without ever editing the bucket policy again.
Scenario 2: Preventing Network Egress Bypasses
A regulated company requires all corporate S3 API calls to originate strictly through AWS PrivateLink Interface VPC Endpoints inside designated company VPCs. The architect wants to prevent developers from accessing S3 buckets over the public internet from home or unapproved networks. Which configuration accomplishes this?
A) Attach an SCP denying s3:* with a condition StringNotEquals: { "aws:SourceVpce": "vpce-xxxxxxxx" }.
B) Disable internet gateways on all corporate VPCs.
C) Configure an AWS WAF rule on Amazon S3 with IP allowlists.
D) Use Route 53 Private Hosted Zones for all S3 traffic.
Correct Answer: A.
Architectural Rationale: The condition key aws:SourceVpce matches the VPC endpoint ID through which the request arrived. When combined with an explicit Deny in an SCP, it prevents S3 operations unless they travel through the authorized PrivateLink VPC endpoint. (Note: WAF does not attach directly to S3 buckets).
