1. Week 1 Capstone: Enterprise Governance Synthesis

Multi-Account Governance Reference Architecture

Week 1 establishes the bedrock of all enterprise cloud deployments on AWS:

  • Account Provisioning: AWS Control Tower + Account Factory for Terraform (AFT).
  • Perimeter Guardrails: Nested OUs with Deny-List Service Control Policies (SCPs) protecting global regions and security tooling.
  • Identity: IAM Identity Center federated with corporate IdP via SAML 2.0 & SCIM.
  • Delegated Permissions: IAM Permission Boundaries for developer autonomy without privilege escalation.
  • Network Plumbing: Central VPC shared across accounts via AWS RAM.

Comprehensive SAP-C02 Scenario Questions

Scenario 1: Comprehensive Landing Zone Governance
A global enterprise needs to design an AWS multi-account governance framework from scratch. The design must provide: (1) automated new account provisioning via Terraform, (2) centralized user login via corporate Okta, (3) non-bypassable guardrails preventing logging deactivation, and (4) shared network subnets without per-account VPC sprawl. Which combination of services delivers this complete solution?
A) Control Tower with AFT + IAM Identity Center with Okta SCIM + Organizations SCPs + AWS RAM VPC Sharing.
B) AWS CloudFormation StackSets + IAM Users with cross-account roles + VPC Peering.
C) AWS Systems Manager + AWS Directory Service + AWS Direct Connect.
D) AWS Organizations alone with default FullAWSAccess and per-account IAM users.
Answer: This represents the modern AWS Well-Architected Landing Zone: Control Tower + AFT for vending, Identity Center for SSO, SCPs for non-bypassable guardrails, and RAM for shared networking.
