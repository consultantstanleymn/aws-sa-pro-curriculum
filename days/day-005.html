1. IAM Permission Boundaries & Delegated Administration

Preventing Privilege Escalation

A Permission Boundary is an advanced IAM feature used to delegate administration to developers without allowing them to escalate their own privileges:

  • When granting a developer permission to create IAM roles (iam:CreateRole, iam:PutRolePolicy), the developer could grant themselves AdministratorAccess.
  • To prevent this, attach a policy to the developer that enforces an iam:PermissionsBoundary condition on all iam:CreateRole and iam:PutRolePolicy calls.
  • The boundary policy explicitly denies modifications to security tools, boundaries, and billing, establishing an unbreakable ceiling.

AWS STS & AssumeRoleWithWebIdentity (OIDC / IRSA)

Modern cloud-native Kubernetes (EKS) and CI/CD workflows avoid static AWS access keys by using IAM Roles for Service Accounts (IRSA) via sts:AssumeRoleWithWebIdentity:

  • EKS serves an OpenID Connect (OIDC) discovery document.
  • Pod service accounts project a signed JWT token.
  • AWS STS validates the JWT against the configured OIDC provider and issues 1-hour temporary credentials mapped directly to the IAM role.

Comprehensive SAP-C02 Scenario Questions

Scenario 1: Delegated IAM Role Creation Without Privilege Escalation
A company wants senior developers to create IAM roles for their microservices on AWS Lambda. The security team must ensure developers cannot create a role that possesses more permissions than their own role or tamper with security audit policies. What mechanism enforces this?
A) Enforce an IAM Permission Boundary requirement on iam:CreateRole with a condition string equals iam:PermissionsBoundary.
B) Use an SCP denying iam:CreateRole across all developer accounts.
C) Create an AWS Config rule to delete unauthorized IAM roles after creation.
D) Use Amazon Cognito User Pools for developers.
Answer: Requiring an IAM Permission Boundary on role creation ensures that any role created by a developer is strictly bounded by the maximum permissions defined in the boundary policy, preventing privilege escalation.
