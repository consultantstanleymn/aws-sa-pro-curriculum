1. IAM Identity Center & Enterprise SAML Federation

Centralized Single Sign-On (SSO) Architecture

AWS IAM Identity Center (successor to AWS Single Sign-On) centralizes access management for all accounts in an AWS Organization:

  • Identity Providers (IdP): Integrates with corporate identity stores including Microsoft Entra ID (Azure AD), Okta, Google Workspace, or CyberArk via SAML 2.0 and SCIM (System for Cross-domain Identity Management). SCIM automatically synchronizes users, groups, and status changes into AWS.
  • Permission Sets: Templates containing AWS managed policies, customer managed policies, or inline policies. When assigned to a user/group on a specific AWS account, IAM Identity Center automatically provisions an IAM role in that account with a trust policy allowing STS federation from the Identity Center service.
  • Session Duration & ABAC: Supports Attribute-Based Access Control (ABAC) using attributes passed in SAML/SCIM assertions to dynamically scope permissions.

Comprehensive SAP-C02 Scenario Questions

Scenario 1: SCIM Synchronization & Access Deprovisioning
An enterprise uses Okta for workforce identity. When employees leave the company, their Okta accounts are immediately suspended, but security discovers former employees could still access AWS consoles for up to 12 hours. How should the architect remediate this vulnerability?
A) Enable SCIM protocol synchronization between Okta and AWS IAM Identity Center and reduce session duration on Permission Sets.
B) Write an AWS Lambda function to delete IAM users every 15 minutes.
C) Apply an SCP requiring MFA token input for every console action.
D) Delete the AWS Organizations Management account credentials.
Answer: SCIM (System for Cross-domain Identity Management) pushes identity lifecycle events (creation, suspension, group membership) automatically.
