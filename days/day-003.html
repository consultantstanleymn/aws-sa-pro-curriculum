1. AWS Control Tower Architecture

Landing Zone Primitives

AWS Control Tower sets up and governs an automated multi-account environment based on best-practice blueprints:

  • Landing Zone Setup: Automatically provisions the Management account, Log Archive account (centralized S3 bucket with KMS CMK encryption and retention), and Audit/Security Tooling account (delegated admin for AWS Config, GuardDuty, and SNS notifications).
  • Guardrails (Controls):
    • Preventative Controls: Implemented via Service Control Policies (SCPs). Disallow actions before they happen.
    • Detective Controls: Implemented via AWS Config Rules and Lambda remediations. Detect non-compliance after resources launch.
    • Proactive Controls: Implemented via AWS CloudFormation Guard hooks before resources are provisioned.

Account Factory for Terraform (AFT)

For organizations practicing GitOps, Control Tower integrates with Account Factory for Terraform (AFT):

  • Uses an event-driven architecture (EventBridge + SQS + Step Functions + CodePipeline).
  • When an account request is merged into the AFT repository, AFT calls Service Catalog / Control Tower to vend the new account, enrolls it into the designated OU, applies baseline SCPs, and executes custom Terraform modules (e.g. deploying standard VPCs, security roles, and logging agents).

Comprehensive SAP-C02 Scenario Questions

Scenario 1: Control Tower Guardrail Types
A security team requires that no developer can disable Amazon GuardDuty in any member account, and any S3 bucket created without server-side encryption must be identified and flagged within 10 minutes. How should these requirements be configured in AWS Control Tower?
A) Deploy a Preventative Guardrail (SCP) to prevent disabling GuardDuty, and an Elective Detective Guardrail (AWS Config rule) for S3 encryption.
B) Write a proactive CloudFormation Hook for GuardDuty and an SCP for S3 encryption.
C) Configure IAM Identity Center permission sets with inline deny statements.
D) Use AWS Firewall Manager to inspect GuardDuty API calls.
Answer: Control Tower uses Preventative Guardrails (SCPs) to stop non-compliant actions and Detective Guardrails (AWS Config rules) to monitor configuration drift.
