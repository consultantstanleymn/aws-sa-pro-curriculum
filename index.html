Curriculum Overview & Strategy

The Solutions Architect Pro (SAP-C02) Mindset

Unlike associate-level exams that test what a service is, the AWS Certified Solutions Architect – Professional tests complex multi-variable trade-offs:

  • Organizational Complexity (26%): Multi-account structures, SCPs, cross-account IAM, centralized auditing.
  • Design for New Solutions (29%): High availability, multi-region routing, decoupled event architecture, secure network ingress/egress.
  • Continuous Improvement for Existing Solutions (25%): Migration methodologies, modernizing legacy monolithic architectures to microservices, cost optimization without compromising performance.
  • Accelerate Workload Migration and Modernization (20%): Database and server migration tools, zero-downtime cutover strategies, hybrid storage solutions.

Phase 1: Multi-Account Governance & Advanced Networking

Governance Security

AWS Organizations, Control Tower & SCPs

Enterprise cloud architecture mandates isolation of concerns across accounts. Never run production and development workloads in the same AWS account.

  • Core OUs: Security OU (Log Archive, Security Tooling), Infrastructure OU (Network Hub, Shared Services).
  • Workload OUs: Production OU, Non-Production OU, Sandbox OU (with aggressive automated teardown).
  • Service Control Policies (SCPs): Explicit deny guardrails. SCPs define the boundaries of what is possible; they do not grant permissions. The management account is never restricted by SCPs.

Production SCP Blueprint: Region & Security Guardrail

Below is an industry-standard SCP template that restricts resource provisioning outside approved regions while preserving global AWS services and preventing security tool tampering:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyUnapprovedRegions",
      "Effect": "Deny",
      "NotAction": [
        "cloudfront:*",
        "iam:*",
        "route53:*",
        "support:*",
        "wafv2:*",
        "health:*"
      ],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:RequestedRegion": [
            "us-east-1",
            "us-west-2"
          ]
        }
      }
    },
    {
      "Sid": "DenyDisablingCloudTrailOrConfig",
      "Effect": "Deny",
      "Action": [
        "cloudtrail:StopLogging",
        "cloudtrail:DeleteTrail",
        "config:DeleteConfigRule",
        "config:StopConfigurationRecorder"
      ],
      "Resource": "*"
    }
  ]
}
Networking

Enterprise Hybrid Networking

Key routing primitives tested on SAP-C02:

  • AWS Transit Gateway (TGW): Hub-and-spoke model connecting thousands of VPCs and on-premises networks. Supports route tables per attachment for network segmentation (e.g. isolating Dev and Prod VPCs).
  • Direct Connect (DX) + Gateway: Dedicated physical network link. Private VIF connects to a Direct Connect Gateway, which attaches to Transit Gateways across multiple AWS regions.
  • AWS Route 53 Resolver: Inbound endpoints allow on-premises DNS servers to resolve AWS private hosted zones. Outbound endpoints forward AWS queries to corporate DNS servers.
  • AWS PrivateLink: Securely expose microservices or access AWS services privately across VPCs without internet gateways, VPC peering, or CIDR overlap conflicts.

Phase 2: Compute, Storage & Database Architectures

Container Orchestration & Serverless Design

Building resilient microservices with Amazon ECS (Fargate) and Amazon EKS:

  • Fargate Spot: Cost-effective compute for fault-tolerant workers with graceful termination handling via SIGTERM and EventBridge notifications.
  • Auto Scaling Lifecycle Hooks: Pause instance termination in an Auto Scaling Group to drain container connections, upload log buffers to S3, and complete in-flight transactions.
  • Event-Driven Decoupling: Amazon EventBridge for cross-account schema-validated routing, Amazon SQS FIFO for strict deduplication and order preservation, Amazon SNS for fan-out architectures.

High-Performance Database Selection

  • Amazon Aurora Global Database: Multi-region disaster recovery with sub-second replication latency and fast unassisted failover (RTO < 1 minute).
  • Amazon DynamoDB Global Tables: Active-Active multi-region replication with two-way reconciliation. Use DynamoDB Streams for real-time change data capture (CDC).
  • Amazon ElastiCache (Redis OSS / Valkey): Write-through vs. Lazy loading caching patterns for sub-millisecond read access and session state offloading.

Phase 3: SRE, Reliability & Observability

SRE Focus

Site Reliability Engineering in AWS

How SRE principles translate to AWS native services:

  • Service Level Objectives (SLOs): Computed using CloudWatch Metric Math on CloudWatch Synthetics canary success rates and ALB 5XX error rates.
  • Distributed Tracing: AWS X-Ray correlated across API Gateway, Lambda, and ECS via trace headers (X-Amzn-Trace-Id) to pinpoint latency bottlenecks.
  • Incident Remediation: EventBridge rules triggering AWS Systems Manager Automation runbooks to reboot degraded nodes or rotate compromised keys.
  • Chaos Engineering: AWS Fault Injection Simulator (FIS) to inject CPU spikes, terminate DB primary instances, and introduce cross-AZ network latency during game days.

Multi-Region Disaster Recovery Patterns

Know the trade-offs between the four Well-Architected DR strategies:

  1. Backup & Restore: Highest RTO (hours) & RPO (hours), lowest cost. S3 Cross-Region Replication (CRR) and AWS Backup.
  2. Pilot Light: Core data replicated in real-time (Aurora read replica, EBS snapshots), minimal compute scaled to zero until disaster. RTO: 10-30 mins.
  3. Warm Standby: Scaled-down version of full environment always running in secondary region. RTO: minutes. Route 53 DNS failover triggers Auto Scaling.
  4. Multi-Region Active-Active: Zero downtime, near-zero RPO/RTO. Traffic routed via Route 53 ARC or AWS Global Accelerator across two live regions. Highest cost and complexity.

Phase 4: Migration & Hybrid Cloud

Enterprise Migration Services

  • AWS Application Migration Service (MGN): Block-level replication of on-premises physical, virtual, or cloud servers into AWS with minimal cutover downtime.
  • AWS Database Migration Service (DMS): Homogeneous and heterogeneous database migration with continuous change data capture (CDC). Combine with AWS Schema Conversion Tool (SCT).
  • AWS DataSync: Automated, encrypted data transfer for petabyte-scale NFS/SMB filesystems to S3, EFS, or FSx.
  • AWS Storage Gateway: Volume Gateway (cached/stored), File Gateway (S3 / FSx), Tape Gateway for virtual tape libraries (VTL).

Phase 5: Practice Scenario Drills & Exam Strategy

Sample Exam Scenario Drill #1

Question: A financial institution runs a core banking platform on Amazon Aurora MySQL in us-east-1. The company has a strict RTO of 5 minutes and an RPO of 1 second for regional disaster recovery. The compliance department also requires that during normal operations, analytical reporting jobs must query read-only data in eu-west-1 without placing load on the primary transactional database in us-east-1. Which architecture fulfills these requirements with the LEAST operational overhead?

  • A) Use AWS Database Migration Service (DMS) with continuous replication from us-east-1 to an Aurora cluster in eu-west-1. Configure Route 53 latency routing.
  • B) Deploy an Aurora Global Database with the primary cluster in us-east-1 and a secondary cluster in eu-west-1. Direct analytical reporting to the reader endpoint in eu-west-1, and configure managed failover in Route 53 Application Recovery Controller (ARC).
  • C) Set up S3 Cross-Region Replication for Aurora database snapshots, and use an automated Lambda function to restore snapshots in eu-west-1 every 15 minutes.
  • D) Use an Aurora Multi-Master cluster spanned across us-east-1 and eu-west-1 with synchronous replication.
Correct Answer: B. Aurora Global Database uses storage-level replication with sub-second replication latency (RPO < 1 sec) and supports cross-region promotion within 1 minute (RTO < 5 mins). Secondary clusters can serve read traffic locally for analytics without impacting the primary cluster. (Multi-Master across regions is not supported, and snapshot restores take too long for a 5-minute RTO).
